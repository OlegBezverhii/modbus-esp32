# modbus-esp32

Пассивный логгер Modbus RTU на шине RS-485. Слушает трафик, режет его на кадры, пишет на SD-карту с метками времени до миллисекунд и показывает последние кадры на OLED. Ничего не передаёт в шину.

Собран на ESP32-C3 (Super Mini) + MAX485 + DS3231 + microSD + SSD1306, управление — энкодером.

## Возможности

- **Пассивный приём.** `DE`/`RE` трансивера посажены на землю: приёмник всегда включён, драйвер всегда выключен. Устройство физически не может мешать обмену.
- **Корректные границы кадров.** Пауза между кадрами считается по t3.5 от текущей скорости (3.5 символа по 11 бит, минимум 1.75 мс для скоростей выше 19200), плюс настраиваемый запас.
- **Метки времени с миллисекундами.** `ЧЧ:ММ:СС.ммм` — локальное время RTC плюс дробная часть из `millis()`.
- **Проверка CRC16.** Каждый кадр помечается `bad`, если контрольная сумма не сошлась.
- **Разбивка лога по времени.** Выкл / 1 / 3 / 5 / 10 / 15 / 30 / 60 минут — после интервала открывается новый файл, запись не прерывается.
- **Контроль места.** Старые логи удаляются при нехватке места, при критическом остатке запись останавливается сама.
- **Разбор на устройстве.** Просмотр лога в hex или в виде разобранных Modbus-кадров (slave, функция, адрес, количество, CRC).
- **Время из GPS** (опционально, NEO-6M) или вручную.

## Железо

| Компонент | Примечание |
|---|---|
| ESP32-C3 Super Mini | 4 МБ flash, USB-C |
| MAX485 (или MAX3485/SP3485) | только приём, `DE`+`RE` на GND |
| DS3231 | RTC с батарейкой CR2032 |
| microSD-адаптер | SPI |
| SSD1306 128×64 | I2C, адрес 0x3C |

### Распиновка

| GPIO | Назначение |
|---|---|
| 0 | энкодер CLK (S1) |
| 1 | энкодер DT (S2) |
| 2 | энкодер SW (кнопка) |
| 7 | SD CS |
| 4 | SD SCK |
| 5 | SD MISO |
| 6 | SD MOSI |
| 8 | I2C SDA (RTC + OLED) |
| 9 | I2C SCL (RTC + OLED) |
| 20 | Modbus RX (RO трансивера) |
| 21 | Modbus TX (DI трансивера, не используется) |
| 3 | GPS TX → ESP32 RX |
| 10 | GPS RX ← ESP32 TX |

### Важно про уровни

MAX485 питается от 5 В, и его выход `RO` в этом случае выдаёт 5 В на пин ESP32 — это выше допустимого. Варианты:

- использовать **MAX3485 / SP3485 / SN65HVD485** и питать от 3.3 В (правильный путь);
- либо оставить MAX485 на 5 В, но поставить делитель/level shifter на линии `RO → GPIO20`.

### Важно про загрузку

`GPIO2`, `GPIO8`, `GPIO9` — strapping-пины ESP32-C3. Кнопка энкодера висит на `GPIO2` и при нажатии тянет его в землю. **Не держи кнопку зажатой в момент включения/сброса** — плата может не стартовать.

### Подключение к шине

- `A → A`, `B → B`, и обязательно общий `GND` (для неизолированного трансивера).
- Не добавляй второй терминатор 120 Ом, если на концах шины он уже есть.
- Не добавляй bias-резисторы — логгер должен быть высокоомным слушателем.
- Если в простое в лог идёт мусор с пометкой `bad`, шине не хватает failsafe-смещения — это нормально для пассивного слушателя, мусор отфильтровывается по CRC.

## Меню

```
Настройка времени   — ручная установка или синхронизация по GPS
Настройки порта     — скорость, запас t3.5, формат (7N1/8N1/7N2/8N2)
Настройки записи    — разбивка файла по времени
Начать запись       — старт логгера
Посмотреть лог      — список файлов, hex или разбор кадров
```

Во время записи экран показывает имя текущего файла, число кадров, число ошибок CRC и интервал разбивки. Кнопка энкодера — стоп.

## Формат лога

Одна строка — один кадр:

```
14:32:07.123 [01 03 00 00 00 0A C5 CD]
14:32:07.456 [01 03 14 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 7B 4A]
14:32:09.001 [FF 3A 91 02 77 12] bad
```

- `ЧЧ:ММ:СС.ммм` — локальное время.
- `[ ... ]` — кадр в hex.
- `bad` — CRC16 не сошёлся (шум, обрыв кадра, неверная скорость).
- `ovf` — кадр длиннее 256 байт (обычно не Modbus).

Имена файлов: `/logs/2026-11-21_14-32-00_log.txt`. При разбивке по времени каждый следующий файл получает время своего открытия.

Старые версии логов (без миллисекунд) читаются тем же парсером.

## Время и часовой пояс

RTC хранит **локальное** время — то же, что показывают часы на компьютере. Это сделано специально: метки в логе и в захвате трафика на Raspberry Pi должны совпадать без пересчёта.

GPS отдаёт UTC, поэтому при синхронизации к нему добавляется смещение:

```cpp
#define TZ_OFFSET_MIN 180   // UTC+3 (Москва)
```

Поменяй на свой пояс (например, `0` для UTC, `60` для UTC+1).

## Разбивка файлов и место на карте

Настройка «Разбивка файла» задаёт интервал, после которого текущий файл закрывается и открывается новый. Ротация выполняется только в паузе между кадрами, так что кадры не рвутся.

Политика по месту:

- при открытии файла, если свободно меньше **128 МБ**, удаляются самые старые логи;
- если во время записи свободно меньше **8 МБ**, запись аккуратно останавливается с сообщением «SD заполнена!».

Обе границы задаются в начале `.ino` (`KEEP_FREE_BYTES`, `STOP_FREE_BYTES`).

Оценка объёма: hex-строка занимает примерно 3 символа на байт шины. Насыщенная шина 9600 — около 250 МБ в сутки, 19200 — около 0.5 ГБ, 115200 — около 3 ГБ. Реальные Modbus-шины обычно загружены заметно меньше.

## Разбор лога на компьютере

Быстрая проверка и разбор:

```python
import re, sys

def crc16(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc

LINE = re.compile(r'^(\d{2}:\d{2}:\d{2}\.\d{3})\s+\[([0-9A-Fa-f ]+)\](?:\s+(bad|ovf))?$')

for raw in open(sys.argv[1], encoding='utf-8'):
    m = LINE.match(raw.strip())
    if not m:
        continue
    ts, hexs, flag = m.groups()
    data = bytes.fromhex(hexs.replace(' ', ''))
    ok = len(data) >= 4 and crc16(data[:-2]) == int.from_bytes(data[-2:], 'little')
    print(ts, f"slave={data[0]}", f"fc=0x{data[1]:02X}",
          "ok" if ok else "BAD", data.hex(' '))
```

Полезные однострочники:

```bash
grep -c ' bad'  logs/*.txt        # сколько битых кадров
grep ' bad'     logs/*.txt | head # посмотреть, как выглядит шум
awk '{print $1}' logs/*.txt | cut -c1-8 | uniq -c   # кадров в секунду по секундам
```

| Симптом | Причина |
|---|---|
| ничего не пишется | не та скорость, `DE`/`RE` не на GND, перепутаны `A`/`B` |
| все кадры `bad` | перепутаны `A`/`B`, нет общего GND, нет терминатора |
| кадры слипаются в один | неверная скорость, увеличь «Запас t3.5» |
| кадры обрезаны | плохой контакт, длинный шлейф, отсутствует терминатор |
| `ovf` в каждой строке | неверная скорость или на шине не Modbus |
| `SD: ERR` | питание, формат карты (FAT32), пайка CS |
| `RTC: ERR` | I2C-адрес, питание, севшая батарейка |
| время уезжает | не выполнена синхронизация, неверный `TZ_OFFSET_MIN` |
| плата не стартует | зажата кнопка энкодера при включении (GPIO2) |
